# Мини-бэкенд на шаблонах C++: от простого к сложному

Учебный репозиторий: 10 коротких уроков, которые на прикладных задачах
бэкенд-разработки последовательно проводят от базовых шаблонов функций до CRTP,
policy-based design и вычислений на этапе компиляции.

Все уроки используют общий домен из `lessons/backend.hpp` (HTTP-запрос и ответ,
статусы, сущность `User`, ошибка БД), поэтому примеры похожи на куски реального
сервиса, а не на абстрактные `foo`/`bar`. Каждый урок — отдельный файл с рабочим
примером и `static_assert`, которые проверяются уже во время компиляции.

## Требования

- Компилятор с поддержкой C++20 (проверено на `g++ 13`).
- `make` (необязательно — уроки собираются и вручную).

## Сборка и запуск

```bash
make          # собрать все уроки в build/
make run      # собрать и по очереди запустить все уроки
make clean    # удалить build/
```

Собрать и запустить один урок напрямую:

```bash
g++ -std=c++20 -Wall -Wextra -Wpedantic lessons/01_function_templates.cpp -o build/01
./build/01
```

## Урок 1. Шаблоны функций

Шаблон функции — это чертёж. Компилятор выводит типы из аргументов вызова и
создаёт отдельную функцию под каждый набор типов.

- `clamp<T>(value, lo, hi)` — ограничение пагинации; работает и для `int`, и для
  `std::size_t` без перегрузок.
- `average_response<Hits, Milliseconds>(...)` — метрика среднего времени ответа;
  тип результата выводится автоматически.
- `config_cast<To>(From)` — явное приведение значения из конфига к нужному типу.
- `json_response<Body>(status, body)` — сборка ответа; тело принимается по
  универсальной ссылке.

Ключевая мысль: шаблон сам по себе не существует, пока его не инстанцируют.

## Урок 2. Шаблоны классов

Класс-шаблон параметризуется типом и создаёт отдельный тип под каждый аргумент.

- `Result<T, E>` — либо значение, либо ошибка (упрощённый `std::expected`),
  фабрики `ok`/`fail` и псевдонимы `value_type`/`error_type`.
- `Cache<K, V>` — кэш пользователей по id, любые ключ и значение.
- `Repository<Entity, Id>` — репозиторий поверх кэша, один на все сущности.

Ключевая мысль: `Cache<int, User>`, `Cache<int, Order>` и `Result<User, DbError>`
— разные, независимые типы, порождённые одним шаблоном.

## Урок 3. Полная специализация

Явная специализация задаёт отдельную реализацию для конкретного типа.

- `JsonSerializer<T>` — общий шаблон без реализации; специализации для `int`,
  `bool`, `std::string` и `backend::User` задают формат JSON.
- `status_text<Status>()` — специализация функции для значений перечисления
  `HttpStatus`, доступна в `static_assert`.

Ключевая мысль: компилятор сначала ищет точную специализацию и лишь потом
берёт общий шаблон.
